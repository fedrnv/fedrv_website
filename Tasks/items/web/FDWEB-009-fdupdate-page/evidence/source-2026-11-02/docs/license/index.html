FDUpdate license decision

Status: approved by the project owner on 2026-10-18.

The owner selected Apache License 2.0 for FDUpdater, the embeddable libraries, FDUpdate-owned server code, examples and documentation. Apache-2.0 provides an explicit patent grant and termination terms and permits commercial use, including competing hosted services. An OSI-approved license cannot promise to exclude such competition.

Alternatives considered:

  • Apache-2.0 alone keeps the patent terms but removes the simple MIT option.
  • MIT alone is simple but lacks Apache-2.0's express patent language.
  • AGPL-3.0 requires corresponding source for modified network deployments and

    • may deter proprietary hosted forks, but adds integration/compliance friction and is not compatible with every intended embedding policy.

The locked Rust dependency graph currently has complete declared license/source metadata and uses permissive expressions (MIT, Apache-2.0, BSD, ISC, Zlib, Unicode, CC0/CDLA-Permissive and compatible alternatives). COT is MIT OR Apache-2.0. Eclipse hawkBit remains a separate unmodified EPL-2.0 service; its license/notices travel with its image and are not relicensed by FDUpdate.

The repository carries the full terms in root LICENSE, workspace package metadata uses SPDX Apache-2.0, and THIRD_PARTY_NOTICES.md identifies separately licensed dependencies and services. Contributions are offered under Apache-2.0. Repository visibility remains separately controlled by the publication checklist.
