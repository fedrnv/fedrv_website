COT service-client integration

FDUpdate Server consumes the current standalone COT service contract rather than embedding COT. The workspace pins COT commit 9f720a6ed5a68dd1fa5df5716fdf7bea57e67c0e, disables default features and enables only cot-sdk/service-client.

The trusted boundary is LocalChannelClient:

  • it accepts loopback HTTP endpoints only;
  • it authenticates with a protected application service credential;
  • channel administration uses cot.private-channels/v1;
  • Telegram setup is write-only and provider secrets remain in COT;
  • list/get/delete use owner-private opaque resources and ETags;
  • delivery uses send_private_message with stable idempotency and correlation

    • identities.

Installation Account email self-service additionally uses COT-0473's published cot.private-email-dynamic-recipient/v1 contract: one application-private channel binds the protected sender/provider setup, and each send supplies one validated recipient. FDUpdate uses the typed SDK pinned above and verifies it against a conforming fake COT service. The project owner confirmed the pinned candidate's complete upstream test/conformance result and deployment. The authorized VPS deployment manifest binds the same commit and the running binary digest; its live health probe passes. FDUpdate's focused typed-fixture, security, UI and deployment verification therefore governs compatibility even while the upstream work item remains open for an unrelated lifecycle reason.

NotificationRuntime owns only FDUpdate's bounded routing/handoff file. COT owns its service database, provider adapters, destination data and process lifecycle. Stopping FDUpdate drops the HTTP client; it must not stop the shared COT service.

Updating COT requires an accepted maintenance task, a full immutable source revision, lockfile update and focused adapter/web tests against the new public contract. Read current COT sources and contract documentation from the COT repository; do not copy private implementation details or modify that repository.

Production COT credentials, bot tokens and chat IDs remain outside this repository. Use an isolated loopback fixture for automated verification and a separately authorized environment for any explicitly approved live delivery check.
