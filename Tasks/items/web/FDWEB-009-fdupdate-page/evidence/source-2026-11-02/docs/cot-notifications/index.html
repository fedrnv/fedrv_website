COT service notifications

FDUpdate Server uses cot-sdk at immutable COT revision dd7496c14bf3526fd93d8b92c00ede34f8ae3c05 with default features disabled and only service-client enabled. FDUpdate does not embed a COT provider, open a COT database, or own the COT process lifecycle.

Enable notifications by setting all three values in the protected fdupdate-web JSON configuration:


{

  "notification_state_dir": "/var/lib/fdupdate/notifications",

  "cot_service_endpoint": "http://127.0.0.1:8081/",

  "cot_service_credential_file": "/etc/fdupdate/cot-service.credential"

}

The endpoint must be loopback. The credential file must be a regular, non-symlink file no larger than 512 bytes and readable only by the FDUpdate service account. COT must authorize that credential as the FDUpdate application. Production credentials, provider secrets and destination identifiers stay outside this repository.

Owners create Telegram channels from /admin/notifications. FDUpdate passes the write-only bot token and chat ID into COT private-channel protected setup; COT owns the secret, destination, channel lifecycle and provider deduplication. FDUpdate stores and displays only COT's opaque channel ID, safe display label, lifecycle state, revision and ETag. It can list, test and conditionally delete its own private channels. Stale ETags fail closed.

FDUpdate persists a bounded event-to-COT handoff before calling send_private_message. A logical message ID binds the event, route, opaque channel ID and channel ETag, so equal ETags on different COT channels cannot collide. The event ID is also passed as correlation ID. Each attempt rechecks that the channel is still ready with the exact bound identity and revision. Changed or removed authority cancels unsent work rather than retargeting it.

States are queued, retrying, in_flight, sent, uncertain, failed, expired and cancelled. sent means COT reported provider acceptance or an already-processed idempotent message; it is not proof that a person read it. Timeout or transport loss after a send is uncertain because the provider may already have accepted the message. Operator retry retains the same logical identity and can still duplicate at a provider that cannot guarantee idempotency.

The handoff remains limited to 4096 jobs, 64 jobs per pass, five admitted attempts, 4096 message bytes and 24 hours lifetime. Feedback and update transactions never depend on COT availability. Rules remain disabled on first creation, previews do not send, repository-scoped administrators see only authorized rule/history projections, and all browser mutations require a valid session and CSRF value.

Legacy v1/v2 embedded-COT handoff files upgrade to v3. Nonterminal legacy jobs are cancelled with cot_service_migration_required; provider credentials and destinations are deliberately not imported from the old embedded state.
