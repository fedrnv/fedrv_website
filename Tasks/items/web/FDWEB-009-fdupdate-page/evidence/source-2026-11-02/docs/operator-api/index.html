Server operator API and CLI

fdupdate-server-api defines the versioned operator request/response contract used by loopback, mTLS or OIDC transports. Credentials are redacted, stored as hashes and compared without content-dependent early exit. Actors receive explicit roles and tenant/product scopes.

Security administrators register products and approve or revoke installations. Release managers publish immutable releases. Fleet operators start, pause, resume or abort rollouts. Readers access bounded status and diagnostics. A valid role never grants another product scope.

Every request ID is bound to the actor and action. An exact retry returns the original response without a second effect; reuse with another action fails. Authorized, denied and failed first decisions enter a SHA-256 hash-chained audit containing actor, action, scope, result and effect ID, without credentials.

parse_cli_action exposes the matching CLI grammar. The transport reads credentials from protected files and supplies them separately; the CLI grammar deliberately has no credential argument.

Focused verification:


cargo test -p fdupdate-server-api --test conformance --locked

cargo clippy -p fdupdate-server-api --all-targets --locked -- -D warnings
