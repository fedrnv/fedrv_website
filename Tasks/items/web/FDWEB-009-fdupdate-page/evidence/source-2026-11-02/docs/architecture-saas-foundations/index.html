SaaS-ready foundations

FDUpdate remains a self-hosted, single-organization product. The fdupdate-saas-foundation crate defines extension contracts needed by a future managed service without adding signup, billing, pricing, or cloud dependencies.

Every application, repository, release, installation key, installation, feedback record, artifact, and audit event has one validated organization owner. Existing server tenant plus repository/product scope is the current ownership source. Authorization compares trusted session/credential scope with stored ownership; client-supplied tenant text never grants access. Colliding IDs across organizations remain distinct and failures deny access.

StorageBackend binds immutable SHA-256/length identities to organization-owned objects. The local backend stays the default. An S3-compatible implementation must pass the same identity, immutability, ownership, corruption, and unavailable-store contract before selection; bucket/object URLs never become authorization.

UsageLedger accepts organization-scoped idempotent event IDs and counts stored bytes, egress bytes, and registered installations. Quota can deny a proposed delta before effect. These are policy hooks, not billing records; they contain no price, payment, invoice, customer secret, or mandatory remote call.

Legacy state migrates only with an administrator-selected default organization. The migration writes explicit owners, validates the result, and retains the pre-migration backup for rollback. It never infers multiple organizations from product names, repositories, hostnames, or credentials.
