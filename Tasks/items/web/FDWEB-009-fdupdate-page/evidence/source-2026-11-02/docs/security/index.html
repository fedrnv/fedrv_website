Security and trust model

Networks and distribution are untrusted. Product-scoped Ed25519 keys authenticate canonical releases and artifacts. Sequence, compatibility, platform, rollout, dependency, installed-version and exact rollback rules are checked locally. Size and SHA-256 are verified before staging. Private signing keys never belong to the updater or a long-running server.

Enrollment binds one public key, instance and tenant/product scope. Pending, denied, revoked, wrong-scope, replayed, or ungranted installations receive no metadata or bytes. Operators have individual roles/scopes, short sessions, CSRF protection, and audit. Secrets use protected files/providers, never releases, browser storage, command arguments, or logs. Store failures deny delivery.

The supported Linux deployment separates the public device gateway from the web owner runtime by UID, primary group, secret directory and mutable state. Their only shared filesystem authority is group read access to the Installation Account document and advisory-lock access to one root-provisioned lock file in a directory neither service can modify. The gateway therefore keeps account authority stable through delegated enrollment without gaining write access to account, self-service or administrator state and without access to administrator, COT or web operator credentials.
